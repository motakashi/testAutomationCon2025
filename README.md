## 設計原則「関心の分離」からPage Object Modelを学ぼう / やまずんさん
生成AIによって変なテストコードが増えてきた
関心の分離：ソフトウェア設計に関与すると考えて形成される思考領域
関心＝考えたり扱う部分　を分離＝分けておく
単一責務の原則＝モジュールを変更する理由はたった1つにすべきであるということ

POMとは、WebUIのテストの操作する部分を、オブジェクト化しておき、分離しておく。
関心の分離
・What（何を検証するか）
・How（どうやって）

単一責務の原則
・同じ理由で変更される→同じ場所で

NG例
・アサーションがPOMの中にある（アサーションはテストコードに入れたほうがいい）
・巨大クラス
・POMの中でデータ生成（データはテストコード側で）
・蜜結合（他のページの遷移が含まれている）

テストはコンテキスト次第

## テスト設計を担うAIエージェントは、どうすればQAチームの仲間入りできるのか？
素のAIに足りないこと
 - 厳密さ・網羅性
 - AIがどの範囲をテストしているかわからない（軌道修正できるようにする）
 - エッジケースが漏れがある（）
   - モデルベースドテスト
   　- テストモデルをAIで生成→それをテストケースに落とすようにする
     - 網羅基準に照らした評価ができるようなった
   - テスト観点DB
   　- テスト観点をツリー化させて、それをもとにエージェントに探索させる
     - スコアが上昇した
 - コンテキストの問題
   - RAGの応用
     - HyDEという手法で大量ドキュメントから目的の機能の仕様を抽出 
     - PDやPJの情報をインプットできるようにする
   - 長期記憶
     - 重要なルールを覚えておく
 - 責任の問題（責任は誰が取るの）
